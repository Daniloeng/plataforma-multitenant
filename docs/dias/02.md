## Decisões e por quê

- **Contratos ao lado do código, verificados no PR.** Um schema que quebra um consumidor vira teste
  vermelho com a lista de incompatibilidades, antes de chegar ao Pulsar.
- **Compatibilidade FULL, não só BACKWARD.** Com BACKWARD, um consumidor antigo quebra quando o
  produtor adiciona um valor de enum. FULL permite implantar produtor e consumidor em qualquer
  ordem; por isso todo enum tem um símbolo default (`OUTRO`).
- **O catálogo de eventos mora nos schemas** (`x-topico`, `x-produtor`, `x-consumidores`). A
  documentação, o código Java e a página do frontend leem a mesma fonte, então não divergem.
- **Linguagem do negócio em português nos contratos** (`pedido.criado`, `valorCentavos`), igual ao
  event storming (ADR-0004).
- **Cliente comprador vem do token** (ADR-0007): o pedido não aceita `clienteId` no corpo.
- **Mermaid carregado sob demanda** no frontend: a página de status não paga o peso dos diagramas.

## Revisão do subagente arquiteto

Antes do PR, o subagente `arquiteto` revisou os contratos e os ADRs e achou 10 problemas. Todos
foram corrigidos neste dia. Os principais:

1. **Ordem entre tópicos.** O texto dizia que eventos do mesmo pedido chegam em ordem, mas isso só
   vale dentro de um tópico. `pedido.cancelado` pode chegar antes de `pedido.criado`, e o pedido
   seria cobrado depois de cancelado. Agora Pagamentos guarda a marca de cancelamento e nunca cobra
   um pedido cancelado (ADR-0006).
2. **Compensações que faltavam:** expiração de pedido PENDENTE (15 min), pagamento aprovado para
   pedido já cancelado, e a fórmula da conciliação com estornos.
3. **Consumidores que faltavam:** Pedidos consome `produto.alterado` (para não vender produto
   inativo); gateway e todos os serviços consomem `tenant.*`.
4. **`clienteId` no corpo do pedido** permitia comprar em nome de outro cliente: virou ADR-0007.
5. **API de Tenants** registrada como plano administrativo; todas as APIs declaram JWT.
6. **Cabeçalhos de identidade vindos de fora** são descartados pelo gateway (ADR-0005).
7. **Chaves de idempotência** sempre com escopo de tenant.
8. O teste de "tenant no corpo" passou a percorrer objetos aninhados e `$ref`.

## Achados do code review do PR (corrigidos)

1. A confiança do Avro 1.12 nas classes geradas só existia nos testes (propriedade do Surefire);
   um serviço real falharia ao ler eventos. Agora `AvroTrust` instala a regra na inicialização do
   `EventCatalog`, sem substituir os padrões do Avro.
2. Cancelar, obter e listar pedidos não recebiam o cliente do token, então não dava para checar o
   dono do pedido. Agora recebem `X-Cliente-Id` (opcional só para o papel gestor-tenant).
3. O workflow de tag dependia da mensagem do commit e lia "08" como octal; agora usa o título do PR.
4. A regra "todo enum tem default" passou a olhar uniões, arrays e mapas.
5. O teste de baseline identificava enums pelo texto do JSON; agora lê o JSON.
6. O extrator de diagramas confundia headings dentro de blocos de código com títulos.
7. O diagrama de contextos passou a mostrar todos os consumidores de `tenant.*`, inclusive o gateway.

## Como testar

```bash
mvn -B verify -pl libs/contracts -am     # contratos: catálogo, compatibilidade e OpenAPI
cd frontend && npm run dev               # http://localhost:5173/#/arquitetura
```

Para ver a regra de compatibilidade funcionando, adicione um campo sem default a um `.avsc` e rode
os testes: o `BaselineCompatibilityTest` falha e diz qual campo e em qual direção.
