# Dia 4: gateway, Keycloak e rate limit por tenant

**Objetivo do dia (plano):** uma porta de entrada única com identidade de verdade. Login no
Keycloak, tenant vindo do token (com troca de tenant para quem atende mais de um), limite de
requisições por plano e os serviços fechados atrás do gateway. No frontend, login e troca de tenant.

## O que foi entregue

| Item | Onde | Observação |
|---|---|---|
| Keycloak | `infra/keycloak/realm-plataforma.json` | Realm `plataforma` importado no Compose (porta 8180). Papéis `plataforma-admin`, `gestor-tenant`, `comprador`; tenants como grupos `/tenants/<id>`; claims `tenants` e `cliente_id`; audiência `plataforma-gateway` |

## Decisões e por quê

- **Tenants como grupos do Keycloak, não um token por tenant.** A ana atende acme e globex; com
  a claim `tenants` ela troca de tenant sem novo login e o gateway confere a escolha a cada
  requisição. Mudança de grupo vale no próximo token (5 min).
- **O gateway reescreve a identidade.** Qualquer `X-Tenant-Id`, `X-Cliente-Id`, `X-Usuario` ou
  `X-Papeis` vindo de fora é descartado antes de o gateway escrever os verificados. Como os
  serviços não têm porta no host, só o gateway fala com eles.
- **Limite em memória, por réplica.** Com uma réplica o limite é exato e não custa um Redis na
  memória do notebook. Com várias réplicas o teto multiplica; isso está no ADR-0009 para o Dia 13+.
- **Catálogo de tenants por eventos.** O gateway não consulta o tenant-service a cada requisição:
  carrega a lista uma vez e se mantém atualizado pelos eventos. Até a carga terminar responde 503,
  para não negar acesso a um tenant válido.
- **Emissor fixo em `localhost:8180`.** O navegador vê o Keycloak em `localhost:8180`, e o gateway
  baixa as chaves por `keycloak:8080` dentro da rede do Compose. `KC_HOSTNAME` fixa o emissor e
  `KC_HOSTNAME_BACKCHANNEL_DYNAMIC` deixa o acesso interno funcionar.
- **Dependências opcionais no `platform-spring`.** O gateway é WebFlux e não pode carregar o
  Spring MVC nem o MongoDB; agora cada serviço declara o que usa.

## Revisão do subagente arquiteto

Antes do PR, o subagente `arquiteto` revisou gateway, realm, Compose, contratos e o ADR-0009. Não
achou forma de forjar identidade, e apontou 7 problemas, todos tratados:

1. **Qualquer grupo virava tenant.** A claim trazia só o nome do grupo, então um grupo
   `/departamentos/globex` daria acesso ao tenant globex. Agora a claim leva o caminho completo e
   o gateway só aceita `/tenants/<id>`.
2. **Um evento ilegível travava o catálogo para sempre** (o consumidor reconectava em `Earliest`
   e caía na mesma mensagem). Agora ela é descartada com log de erro e um contador.
3. **Papéis e cliente são globais do usuário,** não por tenant. Fica como restrição no ADR-0009:
   hoje cada comprador está em um tenant só.
4. **A fronteira dos serviços é a rede.** Registrado no ADR-0009, até a NetworkPolicy do Dia 11.
5. **ADRs 0005 e 0007** citavam a claim `tenant_id`; o status deles aponta para o ADR-0009. O
   ADR-0009 dizia 5 min de token, mas o realm usa 15 min; corrigido.
6. **Chamadas sem tenant não tinham limite.** Agora há um balde por usuário
   (`plataforma.gateway.user-limit`, 20/40).
7. **O cursor da carga inicial ia sem codificação** para a URL; agora usa `URLEncoder`.

## Achados do code review do PR (corrigidos)

1. **`/me` quebrava para quem tem um tenant só** quando esse tenant estava suspenso, ainda não
   cadastrado ou com o catálogo carregando: o gateway escolhia o tenant sozinho e aplicava as
   regras dele. Agora `/me` sem cabeçalho nunca escolhe tenant e usa o balde do usuário.
2. **Falha temporária ao buscar o schema descartava o evento** (ex.: uma suspensão perdida até o
   gateway reiniciar). Agora só mensagens ilegíveis são descartadas; `SchemaLookupException`
   deixa a mensagem sem ack e o consumidor relê.
3. **Um tenant com plano desconhecido travava a carga inicial** (503 eterno). Agora o registro é
   ignorado com log e os outros carregam.
4. **CORS só valia para respostas roteadas.** 401, 403, 429 e `/me` saíam sem
   `Access-Control-Allow-Origin`; o CORS foi para a cadeia do Spring Security.
5. **Limite com `per-second` ou `burst` zero** é recusado na configuração.
6. **`X-Tenant-Id` fora do formato do `TenantId`** responde 400 `tenant-invalido`.
7. **Rota inexistente e serviço fora do ar** respondiam o JSON padrão do Spring Boot; agora saem
   em Problem Details (404 `nao-encontrado`, 503 `indisponivel`).
8. O nome `services/gateway` foge do padrão `<nome>-service`; o CLAUDE.md registra a exceção.

## Problemas encontrados no caminho

1. `docker pull` falhava por DNS no ambiente do Claude: o Docker precisava do proxy. E o
   `quay.io` (registro oficial do Keycloak) é bloqueado; a imagem veio do Docker Hub
   (`keycloak/keycloak:26.4.7`).
2. Rodar o Maven dentro de `services/gateway` não achava o pom pai: os comandos de um módulo só
   rodam da raiz com `-pl ... -am`.
3. O `platform-spring` trazia Spring MVC para todo serviço, o que quebra um serviço WebFlux.
   Resolvido com dependências opcionais.

## Como testar

```bash
docker compose -f infra/docker-compose.yml up -d --build --wait
infra/seed.sh

token() { curl -s localhost:8180/realms/plataforma/protocol/openid-connect/token \
  -d grant_type=password -d client_id=plataforma-cli -d username=$1 -d password=senha123 | jq -r .access_token; }

curl -s localhost:8000/api/v1/me -H "Authorization: Bearer $(token ana)"                   # tenants acme e globex
curl -s -o /dev/null -w '%{http_code}\n' localhost:8000/api/v1/tenants -H "Authorization: Bearer $(token ana)"  # 403
curl -s -o /dev/null -w '%{http_code}\n' localhost:8000/api/v1/me \
  -H "Authorization: Bearer $(token bruno)" -H 'X-Tenant-Id: globex'                         # 403, não é do bruno

# Limite do plano: globex é GRATUITO (5 req/s, rajada 10)
T=$(token ana); for i in $(seq 1 15); do
  curl -s -o /dev/null -w '%{http_code} ' localhost:8000/api/v1/me -H "Authorization: Bearer $T" -H 'X-Tenant-Id: globex'
done; echo

# Suspender um tenant (admin) e ver o 403 tenant-suspenso para a ana
curl -s -X PATCH localhost:8000/api/v1/tenants/globex -H "Authorization: Bearer $(token admin)" \
  -H 'Content-Type: application/json' -d '{"ativo":false}'

# Frontend com login de verdade (http://localhost:5173, entre como ana/senha123)
cd frontend && npm run dev
```
